---
dictionary:
  - id: Aggregate
    name: Aggregate
    summary: "Write-side component that handles commands and emits events for the Transaction and Budget aggregate roots."
    description: |
      The Aggregate is the consistency boundary for all finance operations. All successful state transitions are appended as events to the EventStore.
    icon: Box

  - id: Transaction
    name: Transaction
    summary: "A single financial movement — income or expense — recorded by the user."
    description: |
      Identified by a transaction_id. Lifecycle events: TransactionRecorded, TransactionCategorized, TransactionTagged, TransactionNoteUpdated. Transactions are immutable once recorded; enrichment (categorisation, tagging, notes) is modelled as separate events.
    icon: ArrowLeftRight

  - id: Budget
    name: Budget
    summary: "A user-defined spending limit for a category over a time period."
    description: |
      Lifecycle: BudgetCreated → (BudgetUpdated) → BudgetExceeded → (BudgetDeleted). Budgets track cumulative spending and trigger threshold notifications when limits approach or are breached.
    icon: Wallet

  - id: EventStore
    name: Event Store
    summary: "Append-only log that persists all domain events — the source of truth for the Core domain."
    description: |
      The EventStore holds every event emitted by the Aggregate and injected by the EventInjector. The Projector and BudgetProcessManager consume from this store to build read models and dispatch notifications.
    icon: Database

  - id: EventInjector
    name: Event Injector
    summary: "Service that writes events directly to the event store, bypassing the command pipeline — used for transaction imports."
    description: |
      The EventInjector handles scenarios where events originate outside the normal command flow, such as CSV imports from a bank export. It appends a TransactionImportCompleted event when the import finishes.
    icon: ArrowDownToLine

  - id: Projector
    name: Projector
    summary: "Read-side component that consumes events and maintains denormalised query-optimised views."
    description: |
      The Projector listens to all Core events and keeps three read models up to date: TransactionView (per-transaction list), BudgetView (spending progress), and DashboardView (aggregated financial summary).
    icon: LayoutDashboard

  - id: TransactionView
    name: Transaction View
    summary: "Read model table providing a per-transaction projection for list and search queries."
    description: |
      Maintained by the Projector. Contains denormalised transaction data including category, tags, note, amount, and date.
    icon: List

  - id: BudgetView
    name: Budget View
    summary: "Read model table tracking spending progress and threshold status per budget."
    description: |
      Maintained by the Projector. Tracks how much has been spent against each budget, whether the threshold has been reached, and whether the limit has been exceeded.
    icon: BarChart

  - id: DashboardView
    name: Dashboard View
    summary: "Read model table providing an aggregated financial summary for dashboard rendering."
    description: |
      Maintained by the Projector. Summarises total income, total expenses, net balance, and overall budget health for a user.
    icon: LayoutGrid

  - id: TransactionImport
    name: Transaction Import
    summary: "The process of ingesting transactions from an external source such as a bank CSV export via Enable Banking."
    description: |
      Triggered by the ImportTransactions command. The EventInjector writes TransactionImportCompleted or TransactionImportFailed to the EventStore after the Enable Banking API responds.
    icon: Upload

  - id: BudgetProcessManager
    name: Budget Process Manager
    summary: "Domain process manager that tracks budget state and issues gateway commands for Telegram notifications."
    description: |
      Replays budget lifecycle events (BudgetCreated, BudgetUpdated, BudgetDeleted, BudgetReset, BudgetExceeded, TransactionRecorded) from the EventStore to compute current weekly and monthly remaining amounts. Triggered both reactively (on BudgetExceeded / TransactionRecorded events) and on a daily 8 AM schedule. Produces the SendTelegramMessage gateway command with an HTML-formatted status message including color-coded indicators (🟢 ≥50%, 🟡 ≥25%, 🔴 otherwise).
    icon: Activity

  - id: TelegramGateway
    name: Telegram Gateway
    summary: "Gateway service that delivers HTML-formatted messages to users via the Telegram Bot API."
    description: |
      Subscribes to the SendTelegramMessage gateway command from the BudgetProcessManager and calls the Telegram Bot API /sendMessage endpoint with parse_mode HTML. Configured via TELEGRAM_BOT_TOKEN and TELEGRAM_CHAT_ID environment variables.
    icon: MessageSquare

  - id: BudgetStatusNotification
    name: Budget Status Notification
    summary: "A daily scheduled notification showing remaining weekly and monthly budget amounts."
    description: |
      Triggered every morning at 8 AM by a background scheduler. The BudgetProcessManager replays the event store, computes remaining amounts, formats an HTML status message, and issues the SendTelegramMessage gateway command. The TelegramGateway receives the command and delivers it via the Telegram Bot API.
    icon: Bell

  - id: GatewayCommand
    name: Gateway Command
    summary: "A command dispatched by a process manager to a gateway client for out-of-process side effects."
    description: |
      Gateway commands bridge the domain layer to external systems. Variants include ImportTransactions (handled by the EnableBankingAPIGateway) and SendTelegramMessage (handled by the TelegramGateway). Unlike domain commands, gateway commands do not go through the Aggregate — they are dispatched directly by process managers and handled by gateway services.
    icon: ArrowUpRight
---
